模块概述

Skills（技能）定义Agent"能做什么"——通过触发词激活特定能力集。Hooks（钩子）定义"何时自动做"——通过IDE事件自动触发Agent执行任务。两者配合形成ETL开发助手的"技能矩阵+自动化管线"。

优缺点分析

✅ 优势

  • 技能通过触发词激活，不占用always token预算
  • Hook实现"保存即检查"，零人工介入的质量守门
  • 按钮Hook降低了审计/健康检查的使用门槛
  • 度量和反馈自动采集，持续改进有数据支撑
  • 知识投喂有智能校验引擎，防止错误数据写入

❌ 局限

  • Hook触发后执行时间不可控（大文件审查可能较慢）
  • 无法临时禁用单个Hook（需手动改文件名加_前缀）
  • 技能间无编排能力（不能一个技能自动调用另一个）
  • 部分技能依赖MCP连通性，断连时降级体验不佳

待改进项

🔧 建议

  • P1：支持Hook优先级和并发控制（多文件同时保存时不重复触发）
  • P1：技能编排能力（如需求完成后自动调用审计）
  • P2：Hook执行结果持久化（当前只在对话中显示，不记录历史）
  • P2：技能市场机制（从社区导入新技能定义）
