模块概述

需求处理链路是ETL开发助手的核心对话引擎，定义了从用户提出需求到最终交付SQL脚本和文档的完整流程。v3.0版本引入了"骨架先行"和"多指标编排"机制，通过状态机模型确保每一步都有用户确认门禁，避免跳步或自动推进。

核心设计思想：用户主导节奏，Agent主导专业判断。每个阶段输出结论后停下来等确认，但阶段内的分析、推理、验证由Agent自主完成。

核心设计决策

1. 分叉链路设计（v2.0引入）

新建需求和变更需求走完全不同的路径。新建需求侧重"从无到有"的设计和生成；变更需求侧重"精准定位"和"影响控制"。分叉点在状态2.5，通过关键词+动词类型自动判定。

2. 骨架先行（v3.0引入）

将"设计"拆为骨架（A4a）和字段（A4b），将"SQL生成"拆为骨架（A6a）和填充（A6b）。先确认方向和结构，再展开细节。避免用户在看到大量字段后才发现架构方向有误。

3. 阶段门禁（Anti-Auto-Advance）

规则说明
确认 ≠ 授权下一步用户确认当前阶段不意味着自动进入下一阶段
禁止同回复包含两阶段当前阶段结论和下一阶段输出不能出现在同一条回复中
回退支持用户随时可说"回到上一步"，Agent回退到上一状态

4. 复杂度动态裁剪

判定条件复杂度步骤策略
单指标 + 不新建DWS简单A4a+A4b合并，A6a+A6b合并，A5可跳过
单指标 + 多产品线复杂全部拆分执行
多指标 ≥2 + 同领域复杂+编排触发A0，按批次执行

5. Refined快速通道

当用户引用已精化的PRD文档（refined/*_prd.md）时，跳过大部分澄清步骤，改为"快速校验模式"：从PRD自动提取骨架→MCP验证字段→输出校验结果→确认后直接进入SQL生成。

优缺点分析

✅ 优势

  • 门禁机制杜绝了Agent跳步导致的返工
  • 骨架先行减少方向性错误的修正成本
  • 多指标编排避免重复劳动和口径不一致
  • Refined快速通道显著缩短已精化需求的交互轮次
  • 反例澄清主动发现排除条件，减少遗漏
  • 高完整度快速通道（≥10分跳过逐项澄清）减少无效交互

❌ 局限

  • 简单需求也需要经过多步确认，交互轮次偏多
  • 分类判定依赖关键词匹配，无语义理解能力
  • 跨对话恢复依赖用户主动告知上下文
  • 批量输出时后半部分质量可能系统性下降
  • 门禁过严时用户体验偏"啰嗦"

待改进项

🔧 优先级P1

  • 简单需求的自适应裁剪可更激进（当前仍需3-4轮确认）
  • 跨对话状态持久化（当前对话断开后状态丢失）
  • 多指标快速批次模式的质量保障机制需加强

🔧 优先级P2

  • 分类判定引入语义相似度（替代纯关键词匹配）
  • 自动检测"用户已厌烦门禁"的信号并适当加速
  • 支持并行链路（多需求同时处理）
