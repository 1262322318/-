模块概述

SQL质量管控通过"规范+模板+自动检查"三重机制保障ETL脚本的正确性、可维护性和幂等性。核心思路是：用模板降低出错概率，用Hook自动检测遗漏，用规范统一团队风格。

核心设计 — 幂等性保障

-- 标准幂等模式：先删再插 DELETE FROM dws.target_table WHERE dt_month = DATE_FORMAT(date_sub('${GP_START_DT}', interval 1 month), '%Y%m') AND product_line IN ('冰箱','冷柜') AND zhibiao_type = '2'; -- 老品清零保护（可选，防覆盖历史标记） -- AND model_label_10 <> '老品清零' INSERT INTO dws.target_table(field1, field2, ...) SELECT ... FROM ...;

核心规则：同一组 WHERE 条件的 DELETE 和 INSERT 必须严格对应，确保脚本可任意次数重跑结果一致。

优缺点分析

✅ 优势

  • 17个模板覆盖90%以上的编写场景
  • 保存即检查，问题即时发现不积压
  • 幂等性设计确保脚本可安全重跑
  • 模板从实际项目中提取，贴近真实场景
  • MCP验证字段存在性，避免运行时才发现错误

❌ 局限

  • 快检只覆盖格式和结构，不检查业务逻辑正确性
  • 模板适配新场景时仍需手工调整
  • 没有SQL执行计划分析（性能问题不可知）
  • 无法自动检测SQL语义等价性（重复逻辑）

待改进项

🔧 建议
