🚀 5分钟上手指南

场景一：提一个新ETL需求

  1. 对Agent说 "新需求" 或引用 #etl-requirement
  2. 描述指标名称、业务含义、覆盖产品线
  3. Agent按 A1→A7 流程引导你逐步确认（分类→澄清→匹配→设计→生成）
  4. 最终产出：SQL脚本 + requirement.md + lineage.md + changelog.md

场景二：修改已有指标逻辑

  1. 对Agent说 "修改002的xx逻辑" 或引用refined PRD文档
  2. Agent走链路B：定位→澄清→影响分析→交付模式选择→执行→闭环
  3. 复杂变更用草稿模式：Agent生成draft → 你手工合入 → Agent验证

场景三：投喂知识 / 审计项目

  1. 投喂：说 "投喂知识" → 选类型（表/规则/模式）→ 录入 → 校验 → 写入
  2. 审计：说 "执行项目审计" → 自动检查7个维度 → 生成交互式HTML报告
  3. 文档：说 "生成项目文档" → 生成本套文档

⚠️ 已知边界与不支持项

当前不支持

  • 实时ETL / CDC流处理（仅支持批处理调度模式）
  • 自动执行SQL到生产环境（只生成脚本，部署需人工操作）
  • 跨集群数据同步（限单Doris集群范围）
  • 非结构化数据处理（如图片、日志解析）
  • 自动数据质量告警（当前仅生成验证SQL，不自动执行）

已知局限

  • 知识库为静态文件，不支持多人并行编辑（无锁机制）
  • 模式匹配基于关键词重叠度，不支持语义相似度匹配
  • MCP仅接通PostgreSQL的table_metadata表，非直连Doris
  • 长SQL输出偶有截断风险，需分段确认
  • 外部技能引入、对话样本训练尚在规划中
