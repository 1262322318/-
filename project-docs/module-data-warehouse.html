模块概述

数据仓库采用经典的Kimball维度建模方法论，构建ODS→DWD→DWS→ADS→DIM五层架构。基于Apache Doris 2.1+ MPP引擎，面向海信集团产品效率管理域（IPM），覆盖冰箱、冷柜、洗衣机、空调、日立、视像科技、厨电、激光共8大事业部16条产品线。

数据流转图 — 典型指标链路

以"低效型号占比"为例： 源数据： dim.dim_ipd_productmodel_dd (产品型号属性) ─┐ dim.dim_ipd_salemodel_dd (销售型号属性) ───┤ ods.ods_mr_v_app_fm_imat_saledata (管报) ───┼─→ DWS层计算 dwd.dwd_ipd_ipm_bp_lx_model_mid_dd (规划) ─┤ dw.dim_product_base_info_dd (MDG桥梁) ──────┘ DWS层计算（dws_ipd_ipm_dxmodel_detail_dd）： 1. 产品型号CTE → 产品线分类 + 保护期初判 2. 管报CTE → MDG关联 → 按型号汇总实际销量 3. 规划量CTE → BP/LX选择 → 按型号汇总规划量 4. 最终SELECT → 完成率 = 实际/规划 → is_dx判定 ADS层汇总（ads_ipd_ipm_dxmodel_result_dd）： 5. 从DWS取 is_project='N' 的数据 6. COUNT(is_dx='Y') / COUNT(*) = 低效占比 7. 按 事业部×产品线×内外销 维度交叉输出

优缺点分析

✅ 优势

  • 五层架构职责清晰，各层可独立演进
  • DWS全量保留+标记筛选，支持灵活口径切换
  • DELETE+INSERT幂等，脚本可安全重跑
  • 产品线分类规则统一管理（PUB-003/006），一处修改全局生效
  • MDG桥梁表解耦了管报和型号系统的直接依赖

❌ 局限

  • DELETE+INSERT模式在大数据量时性能不如UPSERT
  • test库中间表占用集群资源，无自动清理机制
  • 跨产品线SQL高度相似但未抽象为通用框架
  • 没有数据质量自动监控（只有手动验证SQL）
  • 历史数据回刷需手动调整参数重跑
