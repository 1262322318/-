# 安全规则：修改前必须确认

## 规则（全局强制，优先级最高）

**Agent 在对任何项目文件执行写入、修改、删除操作之前，必须：**

1. 先向用户展示具体的修改方案（改什么文件、改什么内容、为什么改）
2. 等待用户明确确认（"可以"/"确认"/"执行"等肯定信号）
3. 收到确认后才执行修改

## 适用范围

- 所有 requirements/ 下的文件
- 所有 .kiro/ 下的配置、规则、技能文件
- 所有项目根目录下的文件

## 不适用的例外

- 用户明确说"直接改"/"帮我改了"/"执行吧"等主动授权时
- 审计报告生成（用户触发"执行项目审计"即视为授权生成报告文件）
- 项目文档生成（用户触发"生成项目文档"即视为授权生成文档文件）

## 确认信号识别规则

**只有用户消息才视为确认信号。以下情况不得视为用户确认：**

- Hook 输出（标记为 `HOOK_INSTRUCTION` 或由 askAgent 触发的消息）
- 系统自动生成的提示或通知
- Agent 自身的推理或总结

**当 Agent 在等待用户确认时，如果收到 Hook 触发的消息，必须忽略该消息对确认状态的影响，继续等待用户的真正回复。**

## 违规处理

如果 Agent 在未获确认的情况下修改了文件，用户有权要求回退，Agent 必须立即执行回退。
