# 反馈自动采集技能（傻瓜式）

## 核心理念
测试人员只需要"用"，**所有反馈采集由Agent主动发起**。
工程师不需要：写模板、改文件名、维护任何记录文件。

## 触发方式

### 方式1：每个需求完成后自动询问（强制）
链路A的A7、链路B的B5完成度量后，**自动**向用户问3个简短问题：

```
🎯 本次需求小调研（10秒，请简短回答）

1. 这次体验打几分？(1-5，5最好)
2. 让你最满意的是什么？（一句话即可，可跳过）
3. 让你最不爽的是什么？（一句话即可，可跳过）

直接回复数字和短句即可，例如："4 / SQL生成快 / 澄清问题太多"
```

用户回答后自动写入：`.kiro/data/feedback-records/{YYYYMMDD}-{需求ID}-quickfeedback.md`

### 方式2：用户随时吐槽（被动捕获）
当用户在对话中说出以下信号词时，Agent**自动**进入"吐槽采集模式"：

**吐槽信号词**：
- "这个不好用"、"太麻烦"、"不对劲"、"卡壳"、"傻"
- "希望能"、"要是能"、"如果"、"建议"
- "我吐槽一下"、"反馈一下"、"提个意见"
- "bug"、"有问题"、"出错了"

**Agent行为**：
1. 不打断用户当前任务，**只在背景记录**
2. 在合适的间歇（用户说"好"/"完成"/"继续"等节点）追问1句：
   ```
   刚才你提到"XXXX"，我已记录。能否补充一句具体场景？（也可以跳过）
   ```
3. 用户回答（或跳过）后写入：`.kiro/data/feedback-records/{YYYYMMDD}-{HHMMSS}-issue.md`

### 方式3：用户主动说"反馈" / "吐槽" / "我有意见"
Agent进入引导式采集，3个问题搞定：
```
1. 是关于哪个方面？（需求理解/SQL生成/文档/流程/其他）
2. 具体什么情况？
3. 你希望怎么改？（可跳过）
```

## 采集后的文件结构

每条反馈一个文件，文件名自带分类信息，无需用户起名：

```
.kiro/data/feedback-records/
├── 20260520-009-zhonggaoduan-quickfeedback.md   # 需求结束后的小调研
├── 20260520-143055-issue.md                      # 临时吐槽
├── 20260521-091230-suggestion.md                 # 建议
└── ...
```

### quickfeedback文件格式（自动生成，无需用户填）
```markdown
# 需求快速反馈

- 需求ID: 009-zhonggaoduan-rate
- 操作人: {从Kiro环境获取或对话中识别}
- 时间: 2026-05-20 14:30:55
- 链路类型: A
- 评分: 4/5
- 满意点: SQL生成很快
- 不爽点: 澄清问题问了太多遍同一个口径

## 关联度量
- 度量文件: 009-zhonggaoduan-rate-metrics-20260520.json
- 总轮次: 14
- 主因归类: framework
```

### issue文件格式（自动生成）
```markdown
# 临时反馈/吐槽

- 时间: 2026-05-20 14:30:55
- 操作人: {自动识别}
- 信号词: "希望能"
- 上下文（用户原话）: "希望能直接到Doris跑一下验证"
- 补充说明: "每次都要切到客户端跑很麻烦"
- 严重度: 中（自动判定）
- 分类: 流程优化建议（自动判定）

## 关联会话
（如可关联到当前需求）
- 当前需求ID: 009-zhonggaoduan-rate
- 所在阶段: A6 SQL生成
```

## 严重度自动判定

| 信号词 | 严重度 |
|--------|--------|
| "出错了"/"bug"/"卡死"/"不能用" | 高 |
| "太慢"/"麻烦"/"不对" | 中 |
| "希望能"/"建议"/"要是" | 低 |

## 分类自动判定

| 信号词关键字 | 分类 |
|-------------|------|
| SQL/代码/语法 | SQL生成 |
| 需求/澄清/分类 | 需求理解 |
| 文档/lineage/changelog | 文档生成 |
| 流程/卡壳/确认 | 流程体验 |
| 其他 | 其他 |

## 一键导出（核心功能，独立电脑场景必备）

### 触发方式
用户说"导出反馈" / "打包反馈" / `#export-feedback`

### Agent行为
1. 扫描 `.kiro/data/feedback-records/` 所有文件
2. 扫描 `.kiro/data/interaction-metrics/index.csv` 和详细JSON
3. 生成单个markdown文件：`feedback-export-{操作人}-{YYYYMMDD}.md`
4. 文件位置：项目根目录（方便用户找到）
5. 内容包含：
   - 概览（试用时长/完成需求数/反馈条数）
   - 评分趋势
   - 所有快速反馈聚合
   - 所有吐槽聚合（按严重度排序）
   - 所有度量数据摘要（按瓶颈阶段聚合）
6. 提示用户：
   ```
   ✅ 反馈已打包到: feedback-export-{name}-{date}.md
   你可以直接：
   - 复制全文内容贴到钉钉/微信/邮件
   - 或把文件附件发给项目负责人
   ```

## 项目负责人合并多人反馈

### 触发方式
项目负责人收到多个工程师发来的 `feedback-export-*.md` 后：
1. 把这些文件放到 `feedback/imports/` 目录
2. 说"合并反馈" / `#merge-feedback`
3. Agent自动合并所有文件，识别共性问题，生成 `merged-feedback-{YYYYMMDD}.md`

## 注意事项

- **零模板填写**：用户从不需要打开任何模板文件
- **零文件命名**：所有文件Agent自动起名
- **零目录管理**：用户不需要知道文件在哪
- **失败容忍**：用户跳过任何一个问题都OK，不强制
- **背景记录**：不打断用户当前任务
