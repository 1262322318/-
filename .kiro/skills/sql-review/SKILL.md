# SQL审查技能

## 触发词
用户说以下任意一种时激活本技能：
- "审查SQL"、"review一下"、"检查SQL"
- "帮我看看这个SQL"、"SQL有没有问题"

## 技能说明
对指定的SQL文件执行多维度审查，输出审查报告。可替代部分人工Code Review工作。

## 执行步骤

### 1. 确定审查目标
```
请指定要审查的SQL文件：
A. 输入文件路径（如 requirements/004-sale-model-count/sql_scripts/xxx.sql）
B. 说"当前文件"（审查活跃编辑器中的文件）
C. 说"最近修改"（审查最近一次修改的SQL文件）
```

### 2. 读取SQL并执行审查

Agent读取SQL文件后，按以下6个维度逐项审查：

---

## 审查维度

### 维度1：编码规范（sql_rules.md）

| 检查项 | 规则 | 严重度 |
|--------|------|--------|
| 关键字大写 | SELECT/FROM/WHERE/JOIN/GROUP BY等必须大写 | ⚠️ |
| 缩进一致 | 4空格缩进，层次清晰 | ⚠️ |
| 别名规范 | 禁止a/b/c无意义别名，必须有业务含义 | ⚠️ |
| 行长度 | 每行不超过100字符 | 💡 |
| 注释 | 复杂逻辑必须有注释说明 | ⚠️ |
| 数据类型 | 新建表使用DECIMALV3/DATETIMEV2（Doris 2.1+） | ⚠️ |

### 维度2：性能风险

| 检查项 | 规则 | 严重度 |
|--------|------|--------|
| 全表扫描 | WHERE条件是否利用了分区键 | ❌ |
| 笛卡尔积 | JOIN条件是否完整，是否有ON 1=1（非维度展开场景） | ❌ |
| SELECT * | 禁止使用SELECT *，必须明确字段 | ❌ |
| 大表JOIN顺序 | 小表驱动大表 | ⚠️ |
| 重复子查询 | 相同逻辑是否可以用CTE复用 | ⚠️ |
| DISTINCT滥用 | 是否可以通过JOIN条件避免重复 | 💡 |

### 维度3：业务规则合规

| 检查项 | 规则 | 严重度 |
|--------|------|--------|
| 产品线分类 | 是否正确应用PUB-003/PUB-006 | ❌ |
| 日立口径 | 日立是否使用sale_model_code口径 | ❌ |
| 保护期 | is_project判定逻辑是否完整 | ❌ |
| 库存清零 | 退市+库存为0是否标记为老品清零 | ⚠️ |
| MDG过滤 | product_type_code IN ('FERT','ZTAO') AND delete_flag != 'Y' | ❌ |
| 调度参数 | 是否正确使用${GP_START_DT} | ⚠️ |

### 维度4：幂等性与数据安全

| 检查项 | 规则 | 严重度 |
|--------|------|--------|
| DELETE范围 | DELETE的WHERE条件是否精确，不会误删 | ❌ |
| INSERT字段对齐 | INSERT字段列表与SELECT列数是否一致 | ❌ |
| 老品清零保护 | DELETE是否排除了model_label_10='老品清零' | ❌ |
| 重复执行安全 | 脚本重复执行是否产生重复数据 | ❌ |
| 中间表幂等 | DROP TABLE IF EXISTS是否在CREATE前 | ⚠️ |

### 维度5：字段完整性

| 检查项 | 规则 | 严重度 |
|--------|------|--------|
| INSERT-SELECT对齐 | INSERT列表的字段数与SELECT表达式数一致 | ❌ |
| 字段顺序 | INSERT字段顺序与SELECT表达式顺序对应 | ❌ |
| NULL处理 | 关键字段是否有COALESCE兜底 | ⚠️ |
| 类型匹配 | SELECT表达式类型与目标字段类型兼容 | ⚠️ |

### 维度6：可维护性

| 检查项 | 规则 | 严重度 |
|--------|------|--------|
| CTE命名 | CTE名称是否有业务含义 | 💡 |
| 魔法数字 | 是否有未注释的硬编码数字/字符串 | ⚠️ |
| 代码重复 | 是否有大段重复逻辑可以抽取为CTE | 💡 |
| 变更标记 | 修改过的位置是否有[CHANGE]注释 | 💡 |

### 3. 询问是否自动修复

```
是否需要我自动修复以上问题？
- "修复全部"：自动修复所有可自动修复的项
- "修复错误"：只修复❌错误项
- "不修复"：仅输出报告
```

## 评分规则
- 基础100分
- ❌错误项：-10分/项
- ⚠️警告项：-3分/项
- 💡建议项：不扣分

## 注意事项
- 通过 `#sql-review` 手动引用激活
- 审查时会参考 business_rules.md 中的公共规则
- 审查时会参考 sql_rules.md 中的编码规范
- 如果SQL文件超过500行，分段审查并汇总
