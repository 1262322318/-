# ETL需求分析与澄清规则

## 概述
本文件定义需求分析阶段的完整流程：关键词提取 → 模糊度评分 → 需求澄清 → 数据表匹配 → 分层识别。

## 一、关键词提取

### 业务关键词
| 类别 | 核心词 | 衍生词 |
|------|--------|--------|
| 销售 | 销售、销售额、销量、销额、订单 | 收入、利润、成本、毛利 |
| 产品 | 产品、物料、商品 | 型号、品类、规格、品牌、SKU |
| 区域 | 区域、地区 | 省份、城市、区县、门店 |
| 渠道 | 渠道、通路 | 线上、线下、直销、分销 |
| 客户 | 客户、用户 | 客户类型、客户等级 |

### 技术关键词
| 类别 | 核心词 | 类型词 |
|------|--------|--------|
| 报表 | 报表、报告、看板 | 日报、月报、年报 |
| 分析 | 分析、统计、汇总 | 趋势、对比、排名 |
| 清洗 | 清洗、转换、标准化 | 去重、过滤、映射 |
| 加载 | 加载、导入、同步 | 全量、增量、实时 |

### 时间关键词
| 粒度 | 关键词 |
|------|--------|
| 日 | 日报、每日、天 |
| 月 | 月报、每月、月 |
| 季 | 季报、季度 |
| 年 | 年报、每年、年 |

### 指标关键词
| 类型 | 关键词 |
|------|--------|
| 数量 | 销量、订单量、客户数 |
| 金额 | 销售额、收入、交易金额 |
| 比率 | 增长率、占比、命中率 |
| 排名 | TOP N、排名 |

### 不映射到表的关键词（指示分析方向）
| 关键词 | 指示 |
|--------|------|
| 日报 | 时间粒度=day |
| 月报 | 时间粒度=month |
| 销售额 | 指标字段=sale_amount |
| 销量 | 指标字段=sale_quantity |
| 趋势 | 需要时间序列分析 |
| 统计、汇总 | 需要聚合计算 |

### 权重规则
| 关键词类型 | 权重 | 说明 |
|------------|------|------|
| 核心业务词 | 10 | 决定核心业务领域 |
| 核心技术词 | 8 | 决定技术实现方式 |
| 指标关键词 | 7 | 决定计算指标 |
| 时间关键词 | 6 | 决定时间维度 |
| 辅助关键词 | 3 | 补充信息 |

## 二、模糊度评分

### 评分维度（每项0-2分，0=缺失，1=模糊，2=明确）
| 维度 | 权重 | 明确示例 | 模糊示例 |
|------|------|----------|----------|
| 报表/分析类型 | 高 | "销售日报表" | "做个报表" |
| 分析维度 | 高 | "按产品型号和区域" | "分析一下" |
| 核心指标 | 高 | "统计日销售额和销量" | "看看数据" |
| 时间范围 | 中 | "最近90天" | 未提及 |
| 时间粒度 | 中 | "按日统计" | 未提及 |
| 数据源 | 低 | "从销售数据表" | 未提及（可推断） |
| 输出格式 | 低 | "生成ADS层报表" | 未提及（可推断） |

### 判定规则
| 总分 | 等级 | 处理方式 |
|------|------|----------|
| ≥ 10 | 明确 | 直接进入表匹配，无需澄清 |
| 6-9 | 基本明确 | 少量澄清（1-2个问题） |
| 3-5 | 模糊 | 重点澄清（3-4个问题） |
| < 3 | 非常模糊 | 引导式提问 |

## 三、需求澄清

### 澄清问题优先级
| 优先级 | 缺失维度 | 说明 |
|--------|----------|------|
| P0（必问） | 报表类型 / 分析维度 / 核心指标 | 三者缺任一必问 |
| P1（建议问） | 时间范围 / 时间粒度 | 影响SQL生成 |
| P2（可选） | 数据源 / 输出格式 | 通常可推断 |

### 问题模板

#### 报表类型缺失
```
您需要什么类型的报表/分析？
1. 日报表（每日数据汇总）
2. 月报表（按月汇总统计）
3. 趋势分析（数据变化趋势）
4. 排名分析（TOP N排名）
5. 对比分析（同比/环比）
```

#### 分析维度缺失
```
需要按什么维度进行分析？
1. 产品维度（产品型号、品类）
2. 区域维度（省份、城市）
3. 渠道维度（线上、线下）
4. 时间维度（日、月、年）
```

#### 核心指标缺失
```
需要统计哪些核心指标？
1. 销售额（sale_amount）
2. 销量（sale_quantity）
3. 产品数量（SKU数）
4. 增长率（同比/环比）
5. 占比（区域/品类占比）
```

#### 时间范围缺失
```
需要分析多长时间的数据？（建议：最近30天/90天/12个月）
```

#### 时间粒度缺失
```
数据按什么时间粒度统计？（日/周/月/季度）
```

### 默认值规则
| 维度 | 默认值 | 适用条件 |
|------|--------|----------|
| 时间范围 | 最近30天 | 日报类需求 |
| 时间范围 | 最近12个月 | 月报/趋势类需求 |
| 时间粒度 | 日 | 包含"日报"关键词 |
| 时间粒度 | 月 | 包含"月报"或"趋势" |
| 产品维度 | model_name | 包含"产品型号" |
| 区域维度 | province_name | 包含"区域"或"省份" |

### 交互规则
1. 每次最多问3个问题，避免用户疲劳
2. 按优先级从高到低提问
3. 提供选项让用户快速选择
4. 对已知信息给出默认值建议
5. 用户回答后立即更新分析结果

### 澄清对话模板
```
我理解您需要 [已识别的需求概要]。

为了更准确地生成SQL，还需要确认以下信息：
1. [P0问题]（建议：[默认值]）
2. [P1问题]（建议：[默认值]）

您可以直接回答，或者说"使用默认值"。
```

## 四、数据表匹配

### 匹配流程
```
提取关键词 → 匹配数据表（读取data_mapping.md） → 识别表组合（主表+维度表） → 确定JOIN关系
```

### 主表识别规则
- 关键词匹配到ODS层表 → 识别为主表（别名 `s`）
- 无法确定主表 → 提示用户指定

### 维度表识别规则
- 关键词匹配到 `dw.*` 或 `dim.*` 表 → 识别为维度表
- 使用 LEFT JOIN 关联，确保主表数据完整

### JOIN关系
> 实际映射数据和JOIN关系从 `data_mapping.md` 中获取。

### 输出格式
```
- 主表：`[数据库].[表名]` ([别名])
- 维度表：`[数据库].[表名]` ([别名])，JOIN字段 [字段名]
- 时间粒度：[day/month/year]
- 分组字段：[字段列表]
- 聚合字段：[聚合表达式列表]
```

## 五、分层识别

### 关键词→分层映射
| 分层 | 触发关键词 | 输出表命名 | 用途 |
|------|-----------|-----------|------|
| ADS | 报表、日报、月报、年报、看板 | `ads_{主题}_{粒度}` | 面向业务报表 |
| DWS | 分析、趋势、统计、汇总、对比、排名 | `dws_{主题}_{粒度}` | 面向数据分析 |
| DWD | 明细、清洗、转换、标准化 | `dwd_{主题}_{粒度}` | 面向数据明细 |
| DIM | 维度、分类、属性 | `dim_{主题}` | 面向维度管理 |

### 优先级规则
当需求包含多个分层关键词时：**ADS > DWS > DWD > DIM**
无法确定时默认使用 ADS 层。

### 数据流转路径
| 目标分层 | 流转路径 |
|----------|----------|
| ADS | ODS → DWD → DWS → ADS |
| DWS | ODS → DWD → DWS |
| DWD | ODS → DWD |
| DIM | 源系统 → DIM |

### SQL模板选择规则
| 分层 | 关键词 | 模板 |
|------|--------|------|
| ADS | 日报 | 日报表模板 |
| ADS | 月报 | 月报表模板 |
| ADS | 区域+报表 | 区域分布模板 |
| ADS | 其他 | 通用报表模板 |
| DWS | 趋势 | 趋势分析模板 |
| DWS | 汇总 | 通用汇总模板 |
| DWS | 其他 | 通用分析模板 |
| DWD | 清洗/转换 | 数据清洗模板 |
| DWD | 其他 | DWD事实表模板 |
| DIM | 产品/区域/渠道 | 对应维度表模板 |

## 六、错误处理

| 场景 | 处理 |
|------|------|
| 关键词无法匹配到任何表 | 提示用户确认，建议检查 data_mapping.md |
| 无法确定主表 | 提示用户指定 |
| 无法确定分层 | 默认ADS层，提示用户确认 |
| 分层关键词冲突 | 按优先级选择，提示用户确认 |
| 模糊度评分<3 | 引导式提问，不直接进入分析 |
