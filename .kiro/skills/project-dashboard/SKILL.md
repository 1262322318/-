# 需求看板技能

## 触发词
用户说以下任意一种时激活本技能：
- "看板"、"项目状态"、"需求进度"、"项目看板"
- "今天做什么"、"当前进度"、"需求列表"

## 技能说明
扫描 requirements/ 目录下所有需求，汇总状态、依赖关系和工作建议，输出项目全局视图。

## 执行步骤

### 1. 扫描需求目录

遍历 `requirements/` 下所有子目录（格式：`{ID}-{name}/`），对每个需求读取：
- `requirement.md` → 提取指标名称、状态
- `changelog.md` → 提取最近一次变更记录和日期
- `sql_scripts/` → 检查是否有 `_draft.sql` 文件（表示草稿进行中）

### 2. 判定需求状态

| 状态 | 判定条件 | 图标 |
|------|----------|------|
| 已完成 | 有正式SQL + changelog最近记录标记为✅ | ✅ |
| 草稿中 | sql_scripts/ 下存在 *_draft.sql 文件 | 🔄 |
| 待启动 | intake/ 下有对应文件但 requirements/ 下无目录 | ⏳ |
| 开发中 | 有SQL文件但changelog无✅完成标记 | 🛠️ |

### 3. 扫描 intake 待处理

检查 `intake/` 目录下是否有尚未转为 requirements 的需求文件。

### 4. 构建依赖关系

从 `requirement_patterns.md` 读取依赖字段，构建依赖链：
```
004 → 005 → 006 → 008
004 → 007 → 008
```

识别阻塞：如果上游需求未完成，下游标记为"⚠️ 阻塞"。

### 5. 输出看板

```
═══════════════════════════════════════════
```

## 附加功能

### 需求-脚本-逻辑 三维视图
用户说"三维视图"或"需求逻辑"时，输出每个需求的完整关联：
```
═══════════════════════════════════════════
       📐 需求-脚本-逻辑 三维视图
═══════════════════════════════════════════

┌─ 002 低效型号占比 ─────────────────────────────────────┐
│ 📄 需求文档：requirement.md（已完成）                    │
│ 📊 核心逻辑：实际销量/规划销量<0.8为低效                 │
│ 📝 SQL脚本：                                            │
│    DWD: dwd_ipd_ipm_bp_lx_model_mid_dd.sql（BP/LX拆分） │
│    DWS: dws_ipd_ipm_dxmodel_detail_dd.sql（明细计算）    │
│    ADS: ads_ipd_ipm_dxmodel_result_dd.sql（汇总）        │
│ 📐 应用规则：PUB-001,002,003,004,005,006,008            │
│ 🔗 依赖：无上游 | 无下游                                │
│ 📋 变更记录：外销扩展草稿(2026-05-25)                   │
└──────────────────────────────────────────────────────────┘
```

每个需求展示：需求文档状态 + 核心计算逻辑一句话 + SQL脚本清单 + 应用的公共规则 + 上下游依赖 + 最近变更。
目标：让用户一眼看清"这个需求做了什么、怎么做的、依赖什么"。

### 周报模式
用户说"生成周报"时，额外输出：
```
📋 本周工作摘要（MM-DD ~ MM-DD）
- 完成：{列表}
- 进行中：{列表}
- 下周计划：{基于依赖关系推荐}
```

### 筛选模式
- "看板 草稿"：只显示草稿中的需求
- "看板 阻塞"：只显示有阻塞的需求
- "看板 002"：只显示指定需求的详细状态

## 注意事项
- 通过 `#project-dashboard` 或 `#看板` 手动引用激活
- 不修改任何文件，纯只读操作
- 如果 requirements/ 目录结构不符合预期，提示用户检查
