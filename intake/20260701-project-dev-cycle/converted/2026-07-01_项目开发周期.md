## 二、指标定义

| 字段 | 值 |
|------|-----|
| 指标名称 | 应市项目平均开发周期 |
| 业务含义 | 统计应市类项目从立项到鉴定实际完成的平均开发周期，扣除项目暂停至恢复的时段 |
| 计算公式 | (项目完成时间 - 项目开始时间 - 所有暂停时段累加) 的平均值 |
| 统计口径 | 项目维度 |
| 时间粒度 | 月度（当月完成 + 年累，年累=本年1月到当前月的累计） |
| 覆盖范围 | PS(全部子类)、PA(全部子类)、PB(全部子类)、PC1、PC2、HW、FH类应市产品型号 |
| 维度 | 光模块事业部 / 终端事业部（字段：hbmtpproductline） |
| 内外销 | 不涉及 |

## 三、业务规则

### 核心计算逻辑

1. **单项目开发周期** = hbmtpproductionactualedate(鉴定实际完成时间) - hbmtprojectcreatedate(立项时间) - 暂停时段总和
2. **暂停时段计算**：通过项目调整单表(odsplm_bm_hbmtprojectadjust)，以 projectname 关联项目主表 productname，找到暂停单(HBMTProjectHoldRequest)发布日期和恢复单(HBMTProjectResumeRequest)发布日期，差值为一段暂停时段。多次暂停/恢复则累加所有暂停时段
3. **平均开发周期** = 范围内所有项目开发周期的平均值
4. **"当月完成"判定**：hbmtpproductionactualedate(鉴定实际完成时间)落在统计当月
5. **统计范围**：
   - 项目类型字段(HBMTPDERIVETYPE)为 PS(含PS1/PS2/PS3等全部子类)、PA(含全部子类)、PB(含全部子类)、PC1、PC2、HW、FH
   - 项目状态(projectcurrent) IN ('Complete','Review','Archive')
   - 取消项目(HBMTProjectCancleRequest)不纳入统计

### 项目状态枚举（projectcurrent字段）

| 状态值 | 中文含义 | 是否纳入统计 |
|--------|----------|-------------|
| Complete | 完成 | ✅ 是 |
| Review | 复核 | ✅ 是 |
| Archive | 归档 | ✅ 是 |
| Hold | 暂停 | ❌ 否 |
| Cancel | 取消 | ❌ 否 |
| Concept | 概念 | ❌ 否 |
| Create | 项目立项 | ❌ 否 |
| Assign | 分配 | ❌ 否 |
| Active | 活动 | ❌ 否 |

### 汇总指标计算公式

| 指标 | 公式 |
|------|------|
| 完成率 | 2 - 实际值/目标值 |
| 同比改善 | 1 - 实际值/同期值 |

### 特殊规则

- [x] 暂停扣除规则：暂停重启项目，项目暂停至项目重启的时间段不纳入开发周期统计。暂停时段 = 恢复单发布日期 - 暂停单发布日期。多次暂停累加所有暂停时段
- [x] 取消项目：不纳入统计
- [x] 项目状态筛选：projectcurrent IN ('Complete','Review','Archive')

## 六、原始素材

> 以下为PRD文档提取的核心信息，原样保留供追溯。

### 业务背景
每月需从现有系统手动导出包含所有项目状态的原始报表。由于报表数据量大且内容多，需人工逐一筛选出当月实际完成的项目，过程繁琐且耗时；筛选出后还需手动查询每个项目的实际开始日期和实际完成日期，并计算开发周期。此过程易因人为因素导致数据不准确。

### 产品目标
1. 开发应市项目开发周期统计功能，从PLM系统获取项目原始数据和产品线维度
2. 开发前端展示报表，实现应市项目开发周期的展示监控
3. 数据应用上线前每月手工工时4.5H，上线后解决4H
4. 准确率可提升至100%
