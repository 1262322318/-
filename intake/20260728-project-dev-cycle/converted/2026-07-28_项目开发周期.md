### 业务背景
每月需从现有系统手动导出包含所有项目状态的原始报表。由于报表数据量大且内容多，需人工逐一筛选出当月实际完成的项目，过程繁琐且耗时；筛选出后还需手动查询每个项目的实际开始日期（如需求确认日期 / 开发启动日期）和实际完成日期（如测试通过日期 / 上线日期），并计算开发周期。此过程易因人为因素导致数据不准确。人工完成数据收集和处理效率低，不利于及时发现问题、总结经验，需求转为自动化报表。

### 产品目标（可量化）
1. 开发应市项目开发周期统计功能，从 PLM 系统获取项目原始数据和产品线维度。
2. 开发前端展示报表，实现应市项目开发周期的展示监控。
3. 数据应用上线前，每月手工做表工时 4.5H；上线后工时节省 4H。
4. 其他预期收益：实现项目完成状态自动识别、开发周期自动计算、报表自动生成与导出，将团队成员从繁琐重复的人工操作中解放出来，专注于更具价值的项目管理和问题解决工作；每月至少减少 4H 人力投入，准确率可提升至 100%。

- 完成率 = 2 − 实际值 / 目标值（实际值越小越好）
- 同比改善 = 1 − 实际值 / 同期值（同期值 = 去年同月）

## 三、业务规则

### 核心计算逻辑
- 项目开发周期 = 项目完成时间（HBMTPPRODUCTIONACTUALEDATE）− 项目立项时间（HBMTPROJECTCREATEDATE）。
- 对统计范围内的所有项目的开发周期取平均，得到"应市项目平均开发周期"（统计粒度：按项目【发起人 2026-07-31 确认】）。
- 统计范围：应市类项目，由 `HBMTPDERIVETYPE` 判定，取值 PA（全部）、PB（全部）、PC1、PC2【发起人 2026-07-31 确认】。
- "实际完成时间"为当月的项目纳入当月统计。

### 特殊规则
- [x] 暂停 / 重启规则：项目暂停至项目重启的时间段不纳入开发周期统计。进度统计里"重启时间 − 取消 / 暂停时间"（时间均按发布时间）。
- [x] 暂停单获取逻辑：PLM 需新增变更单表 `PLMASSIST.HBMTPROJECTADJUST`。通过该表获取暂停单发布日期；根据 `PLMASSIST.HBMTPROJECTKPI` 获取 `PRODUCTNAME`，结合项目调整单 `PLMASSIST.HBMTPROJECTADJUST` 中项目名称 `PROJECTNAME` 进行联合查询；根据申请单发布时间得出项目暂停单发布时间、项目恢复单发布时间，进而得出项目暂停日期范围。
- [ ] 剔除条件：无（源文件未额外定义）
- [ ] 库存相关：不涉及
- [ ] 其他：目标值为手动维护，暂用一张模拟表【发起人 2026-07-31：暂未定，模拟表的结构/字段/取数粒度作为遗留项在建模阶段确定】。
