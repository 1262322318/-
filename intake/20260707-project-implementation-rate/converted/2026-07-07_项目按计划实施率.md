## 二、指标定义

| 字段 | 值 |
|------|-----|
| 指标名称 | 应市项目按计划实施率 |
| 业务含义 | 统计应市类项目中正常执行+按期结题的项目占比，反映项目执行的健康度和计划达成能力 |
| 计算公式 | (正常项目数 + 结题项目数) / (正常项目数 + 延期项目数 + 暂停项目数 + 结题项目数) |
| 统计口径 | 项目维度（按项目个数计数） |
| 时间粒度 | 月度（当月快照） |
| 覆盖范围 | PS(全部子类)、PA(全部子类)、PB(全部子类)、PC1、PC2、HW、FH类应市产品型号 |
| 维度 | 事业部（终端事业部/光模块事业部）、产品线（BOX/机顶盒等）、项目经理 |
| 内外销 | 不涉及 |

## 三、业务规则

### 纳入统计范围

1. **项目分类筛选**：HBMTPDERIVETYPE 字段用LIKE前缀匹配（如 LIKE 'PS%'、LIKE 'PA%'、LIKE 'PB%'、LIKE 'PC1%'、LIKE 'PC2%'、LIKE 'HW%'、LIKE 'FH%'）
2. **项目类型**：应市类（HBMTPPROJECTTYPE='应市类'）
3. **活跃项目判定**：
   - 鉴定实际完成时间(hbmtpproductionactualedate)为空时，项目状态(projectcurrent)为 'Assign'(分配)、'Active'(活动)、'Create'(项目立项) 的项目
   - 或：鉴定实际完成时间落在统计当月的所有项目（不限状态）

### 项目情况判定（5种互斥状态）

| 状态 | 判定规则 | 是否纳入合计分母 |
|------|----------|-----------------|
| 结题 | 鉴定实际完成时间(hbmtpproductionactualedate)落在统计当月 | ✅ 是 |
| 延期 | 非结题项目中，开发或鉴定阶段存在延期（实际完成时间 > 计划完成时间 + 3个工作日） | ✅ 是 |
| 暂停 | 项目状态(projectcurrent) = 'Hold' | ✅ 是（累计展示，纳入分母） |
| 终止 | 项目状态(projectcurrent) = 'Cancel'，且取消单发布日期在当月，且当月内没有恢复单 | ❌ 否（当月展示，不进分母） |
| 正常 | 不属于上述任何一种 | ✅ 是 |

**判定优先级**：结题 > 延期 > 暂停 > 终止 > 正常

### 延期判定详细规则

延期 = 开发阶段延期 OR 鉴定阶段延期（任一即为延期）

| 阶段 | 计划时间字段 | 实际时间字段 | 延期判定 |
|------|-------------|-------------|----------|
| 设计性试制（开发） | hbmtpdesignestimatededate | hbmtpdesignactualedate | 实际完成时间 > 计划完成时间 + 3个工作日 |
| 生产线试制（鉴定） | hbmtpproductionestimatededate | hbmtpproductionactualedate | 实际完成时间 > 计划完成时间 + 3个工作日 |

**"+ 3个工作日"计算方式**（基于 ods.odsrdm_holiday 表）：
1. ods.odsrdm_holiday 表结构：id(排序用), date_time(仅存储工作日)
2. 找到计划完成时间在表中等于或最接近的下一个工作日（若计划完成时间为非工作日则顺延到下一工作日），获取对应 id
3. id + 3 对应的 date_time 即为"计划完成时间 + 3个工作日"
4. 若实际完成时间 > 该日期，则判定为延期

**注意**：已判定为"结题"的项目不再参与延期判定

### 终止判定详细规则

1. 项目状态 projectcurrent = 'Cancel'
2. 在 odsplm_bm_hbmtprojectadjust 表中，type = 'HBMTProjectCancleRequest' 的记录，releasedate 落在统计当月
3. 同一项目在当月内不存在 type = 'HBMTProjectResumeRequest' 的恢复记录

### 暂停判定规则

- 项目状态 projectcurrent = 'Hold'
- 暂停为累计展示（不区分当月/非当月），报表中展示"暂停(累计)"列

### 合计与实施率计算

- **合计** = 正常项目数 + 延期项目数 + 暂停项目数 + 结题项目数
- **按计划实施率** = (正常项目数 + 结题项目数) / 合计 × 100%

### 产品线分类规则

| 事业部 | hbmtpproductline 字段值 | 产品线展示名 |
|--------|------------------------|-------------|
| 终端事业部 | emxFramework.Range.HBMTPProductLine.BOX | BOX |

| 光模块事业部 | emxFramework.Range.HBMTPProductLine.Coherent | 相干产品线 |

**不纳入统计的产品线**：A5(OSA)、A7(芯片产品线)、A8(技术预研部) — 这些产品线的项目不纳入统计范围，只统计终端和光模块

## 六、原始素材

> 以下为PRD文档提取的核心信息，原样保留供追溯。

### 业务背景
每月需从现有系统手动导出包含所有项目状态的原始报表。由于报表数据量大且内容多，需人工逐一筛选出当月活动、暂停、取消、完成状态的项目个数，区分项目所属产品线并记录数据，过程繁琐且耗时；还需手动计算每个产品线当月的项目按计划实施率，并按项目经理统计每人负责的项目数和实施率，此过程易因人为因素导致数据不准确。

### 产品目标
1. 从PLM系统获取项目原始数据和产品线维度
2. 开发前端展示报表，实现应市项目按计划实施率的展示监控
3. 数据应用上线前每月手工工时4.5H，上线后解决4H。年收益约50H

### 用户旅程
1. 登录信数，进入"研发管理"版块
2. 选择时间维度、其他业务维度
3. 系统刷新报表数据，用户确认无误关闭；确认有问题查看明细数据
