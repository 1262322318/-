一、链路全景（分叉链路v2.0）

二、需求分类判定（状态2.5）

这是分叉链路的核心节点，通过以下7条优先级规则判定需求类型：

优先级判定条件分类结果进入链路
1提及已有需求ID（如"004"、"002"）+ 变更动词变更需求链路B
2提及已有指标名称 + 变更动词（修改/加/改/删/调整/扩展）变更需求链路B
3包含Bug/错误/问题/不对/修复 + 提及已有指标变更需求（Bug修复）链路B
4包含"新增/新建/创建/开发" + 未命中任何已有模式全新需求（独立型）链路A
5包含"新增" + 命中已有模式 + "基于/参考/类似"全新需求（依赖型）链路A
6命中已有模式（≥60%）+ 无变更动词全新需求（相似型）链路A
7无法判定询问用户等待确认

动词库

新建动词库

新增（指标/需求）、新建、创建、开发、做一个、统计一个

变更动词库

修改、改、调整、优化、加、新增（字段/逻辑/产品线）、删除、去掉、修复、修正、扩展、补充、完善、更新

判定后输出模板

【需求分类判定】 我判断这是一个 [全新需求/变更需求]： - 类型：[独立型新指标 / 依赖型新指标 / 相似型新指标 / 逻辑变更 / 产品线扩展 / 字段新增 / Bug修复 / 规则变更] - 关联需求：[无 / 需求ID] - 判定依据：[说明为什么这样判定] 请确认是否正确？如果不对请告诉我正确的类型。

三、链路A：新建需求流程（A1~A7）

A1依赖识别

项目内容
触发条件需求分类为"全新需求"且用户已确认

A2需求澄清（新建专属）

需求子类型澄清方式必问项
独立型完整澄清（7项）指标名称/计算公式/覆盖产品线/管理口径/时间粒度/数据来源/特殊规则

相似型差异澄清（2项）与参考需求的差异/新增的维度或指标
交互规则：每次最多问3个问题，每个问题必须等用户回答后再问下一批，用户回答后立即总结确认。

附：全局规则

阶段门禁（Gate）

核心原则：每个状态的退出都需要用户明确确认。Agent不得在未获确认的情况下进入下一状态。

确认信号："确认"、"可以"、"没问题"、"对的"、"正确"、"继续"
否定信号："不对"、"不是"、"修改"、"调整" → 停留在当前状态修正
模糊回复：追问"请确认是否可以进入下一步？"

回退规则

用户指令Agent行为
"回到上一步" / "重新来"回退到上一状态
"取消" / "不做了"回到状态1

错误处理

场景处理方式
无法判定需求分类直接询问用户
表匹配失败提示用户确认表名
SQL生成失败说明原因，建议简化
