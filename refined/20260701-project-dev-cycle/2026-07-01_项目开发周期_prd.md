## 四、业务规则

### 4.1 时间规则

| 项目 | 业务描述 | 字段 | 说明 | 确定度 |
|------|----------|------|------|--------|
| 起点 | 立项时间 | `hbmtprojectcreatedate`（备注：立项时间） | 项目创建日期 | 确定 |
| 终点 | 鉴定实际完成时间 | `hbmtpproductionactualedate`（备注：鉴定实际完成时间） | 项目实际完成日期 | 确定 |
| 当月判定 | 完成时间落在统计月 | `hbmtpproductionactualedate` | 年月匹配当前统计月 | 确定 |
| 年累范围 | 本年1月到当前月 | `hbmtpproductionactualedate` | 年份=当年 且 月份≤当前月 | 确定 |

### 4.2 计算规则

| 规则项 | 内容 | 确定度 |
|--------|------|--------|
| 单项目开发周期 | DATEDIFF(hbmtpproductionactualedate, hbmtprojectcreatedate) - 暂停时段总和(天) | 确定 |
| 暂停时段计算 | 通过adjust表关联：SUM(恢复单releasedate - 暂停单releasedate)，按projectname关联productname | 确定 |
| 多次暂停处理 | 累加所有暂停时段（一个项目可能有多次暂停/恢复） | 确定 |
| 平均开发周期（当月） | AVG(当月完成的所有项目的开发周期) | 确定 |
| 平均开发周期（年累） | AVG(本年1月到当前月完成的所有项目的开发周期) | 确定 |
| 按类型分组 | 按HBMTPDERIVETYPE前2位分组（PS/PA/PB/PC/HW/FH），PA含PA1/PA2等子类 | 确定 |
| 完成率 | 2 - 实际值/目标值（天数越少完成率越高） | 确定 |
| 同比改善 | 1 - 实际值/同期值（天数减少则改善为正） | 确定 |

### 4.3 暂停时段关联逻辑

```
项目主表.productname = 调整单表.projectname
```

对同一个项目按 releasedate 排序，配对暂停单和恢复单：
1. 找到 type = 'HBMTProjectHoldRequest' 的记录，取其 releasedate 为暂停开始日期
2. 找到 type = 'HBMTProjectResumeRequest' 的记录，取其 releasedate 为暂停结束日期
3. 暂停时段 = 恢复日期 - 暂停日期（天）
4. 一个项目可能有多段暂停，累加所有暂停时段

### 4.4 目标值解析逻辑

目标值表 record_data 字段为 JSON 格式：
```json
{"时间":[{"text":"2026","type":"text"}],"目标值":[{"text":"346","type":"text"}],"类型":[{"text":"终端","type":"text"}],"维度":[{"text":"PA","type":"text"}]}
```

解析规则：
- `时间` → 年份
- `目标值` → 目标天数
- `类型` → 维度（终端/光模块事业部）
- `维度` → 项目类型分组（PA/PB/PC/平均）

### 4.5 汇总报表计算

#### 报表一：总指标表
- 行维度：光模块事业部/终端事业部 × 类型(PA/PB/PC/平均)
- 列维度：目标、1月~12月实际值
- 分两组：当月、年累
- "平均"行 = 该事业部下PA+PB+PC的加权平均（按项目数加权）

#### 报表二：汇总对比表
- 行维度：光模块事业部、终端事业部、公司
- 列维度（当月）：PA实际、PB实际、PC实际、实际值(综合)、同期值、目标值、完成率、同比改善
- 列维度（累计）：同上
- 公司行 = 两个事业部的加权平均

- 禁止将暂停时段设为0处理（必须关联adjust表计算实际暂停天数）
- 禁止对HBMTPDERIVETYPE使用精确匹配'PA'（应使用LIKE 'PA%'匹配PA1/PA2等子类，PS/PB同理）
